【A 数据层（预计算缓存）】
1. 烘焙：加载时逐帧求值一组固定骨骼（骨盆、脊柱、大腿、膝、踝、脚跟、脚尖/脚掌）的世界矩阵 → numpy，存成 .npz，按 op log 版本号缓存。写操作只让受影响的帧段（±余量）失效重算。烘焙在主线程用 timers 分块跑，界面不卡。
2. 信号注册表：在烘焙结果上算出一批「有名字的信号」，每个带单位和一句话说明，例如：
foot.L.toe.h / foot.L.heel.h（高度 m）、foot.L.speed_xy、foot.L.yaw / yaw_rate（度、度/帧）、foot.L.pivot（脚尖和脚跟哪个点更静止）、foot.L.pen（穿地深度）、pelvis.h / speed / acc / jerk、<骨骼>.rot_speed、hf_loss.<骨骼>（原始 vs 当前的高频能量差 = 力量感丢了多少）、contact.L / jump / jitter（来自你的可靠区间，0/1）。
这张表（名字 + 单位 + 说明）直接写进系统提示词，LLM 按名字点菜。
3. 原始数据：滤波前的 Action 也烘焙一份，所有信号都能加 source=raw 取。

【B 查询工具（全部 JSON 参数 + schema 校验）】
1. get_overview()：帧范围、fps、信号列表、标注清单（id/范围/标签/备注）、各类区间数量。
2. list_intervals(kind, frame_range?, tag?)：按类型列区间，给稳定 id。
3. describe(target, channels?, context=true)：target 可以是区间 id 或帧范围。返回每个信号的 min/max/mean/std、首尾值、极值所在帧，加上前后各 N 帧的同样统计做对比，以及区间内的事件（着地切换、加速度峰值）。channels 不填就按标签用默认组合（pivot → yaw、yaw_rate、脚尖脚跟高度和速度；force → acc、jerk、hf_loss；ground → 高度、pen）。这就是「摘要卡片」。
4. get_series(channels, frame_range, max_points=60, agg=mean|max|min)：自动选步长下采样，点数有硬上限，返回 {frames:[…], 各信号:[…]}。
5. find_events(cond, frame_range?)：声明式条件，不让 LLM 写代码。例：{"all":[{"ch":"foot.L.heel.h","op":"<","v":-0.005},{"ch":"contact.L","op":"==","v":1}],"min_len":2} → 返回所有满足的区间。只允许白名单运算符和 and/or，能安全组合。
6. compare(channel, a, b)：a/b 是两个区间，或同一区间的 raw vs current，返回峰值比、均值差、DTW 距离。
7. snapshot(frame, bones?)：某一帧关键关节的位置和角度，看细节用。
8.（可选）plot(channels, frame_range)：用 matplotlib 画张小图给多模态 LLM，看曲线形状比看数字直观得多。

【C 让 LLM 用得好的规则】
· 渐进式：overview → list → describe → 不够再 get_series / find_events，提示词里写明这个顺序。
· 每个返回都有大小上限（约 1~2k token），超了就截断并提示怎么缩小范围。
· 参数错就给可操作的报错：「没有 foot.L.yaw_rat，是不是想要 foot.L.yaw_rate？」
· 单位、坐标系（Z 朝上、地面高度）、帧范围含不含端点，统一写死并在返回里带上。
· 同样的查询返回同样的结果（走缓存），方便 LLM 前后对比。

【D 验证】
拿几段已知问题的片段做「找茬测试」：让 LLM 只用这些工具去找穿地、悬空、候选 pivot，统计找全率和平均调用次数，用来调默认信号组合和返回格式。

这样 LLM 只需要说「看哪个信号、哪一段、要多细」，数据层负责算好、压缩好再递过去！

【通用约定】
· 每个写工具都有 mode=preview|commit：preview 写到临时 NLA 层，返回「前后指标 + 违规清单」；commit 才落到 agent 层、写 op log、undo_push。
· 只改控制器（脚 IK、torso、脚尖等）的 F-curve，你之后还能接着手调。agent 层用 NLA 的 Combine 混合（四元数会正确相乘），别用 Add。
· 每个操作都带 blend_in / blend_out（默认 4~6 帧，smoothstep 权重），保证边界处位置和速度连续。
· 统一返回：op_id、影响帧段、前后指标（用输入端那套信号算）、violations。

【工具清单】
1. clean_jitter(controllers, frame_range, strength)：只在抖动区间里做零相位平滑（如 Savitzky-Golay），区间外不动，着地脚的锁定位置不变。
2. fix_ground(foot, frame_range, mode=lift|pen|float, pin_xy?)：着地段把脚 IK 高度设到「地面 + 静止时脚尖/脚跟高度」，脚底按着地类型压平；pin_xy=true 时 XY 钉在区间均值，顺便去滑步；跳跃区间自动跳过；最后自动调用 solve_pelvis。
3. solve_pelvis(frame_range, target=keep_ratio|reach_only)：keep_ratio 让着地腿的「髋到脚 / 腿长」等于源数据，双脚着地取更低的解；reach_only 只在够不着时下沉。低通后再夹一次约束，写进 torso。
4. 脚步（样例迁移三件套）：
 · register_exemplar(foot, frame_range, tag)：你 k 完后调用。抽残差 → 转到着地起点的局部系 → 存签名（转向速度序列、着地模式、时长），自动生成镜像版。
 · find_matches(exemplar_id, top_k, min_score)：在着地区间里做 DTW，返回候选和分数，给你打勾用。
 · apply_exemplar(exemplar_id, interval, time_align=keypoints|linear, scale_yaw=auto, mirror=auto)：对齐、时间缩放、按实际转角缩放、叠残差、两端渐变，把区间加进「不自动锁脚」名单，再调 solve_pelvis。
5. 力量感 restore_accent(controllers, frame, window, strength 0~1, method)：
 · hf_reinject：窗口内把（原始 − 当前）的带通残差 × strength × 窗函数补回去
 · ease_reshape：冲击帧前收紧缓入让加速更陡，之后加 x% 过冲再回落
 · retime：窗口内做时间重映射，压缩发力段、拉长回收段，端点不动
 · refilter：窗口内用更弱的滤波重做一遍，再交叉淡化
 返回峰值加速度相对原始的比值（目标约 0.8~1.0）和 jerk 变化。映射规则写进提示词：「没劲、太软」→ hf_reinject 或 ease_reshape；「拖沓」→ retime。
6. validate(frame_range?)：穿地、着地滑移、区间外新增的高频能量、膝盖超伸/关节限位、边界位置和速度跳变。每次写完自动跑，有违规就拒绝 commit（你手动 force 除外）。
7. 管理：list_ops / revert(op_id) / commit(op_id) / discard(op_id) / set_preview(frame_range)（设播放范围、开 Motion Paths 给你看）。
