## 2. 任务1：多 agent 并发安全

**问题**：所有 agent 共用一个全局 `version`；读工具内部的 `frame_set` 也会触发 depsgraph 回调把它推高。
3–5 个 agent 同时干活时，`expect_version` 几乎每次都过期——agent 互相"误伤"、反复重读。

**设计**（咨询性租约，不是锁；GUI 里的用户永远不受限）：

| 机制 | 行为 |
|---|---|
| `claim {agent_id, bones/chain, frames, ttl_s}` | 同骨 + 帧重叠的别人 → 不批（给出占用者、重叠帧）；父子骨重叠 → 批 + related 警告（`strict` 则不批）；`check_only` 只查；TTL 15 min，活动即续期 |
| 写入检查 | 每个写工具都有 scope（旧工具解析参数；插件工具 `WRITE_SCOPES`；reapply/revert/set_influence 用 op 实际写过的骨）。落在别人 claim 里 → `E_CLAIMED`；空闲 → 自动认领 |
| scope 化 `expect_version` | 写入日志记 (version, owner, 骨, 帧)；过期仅当期间**别人**改了**同骨或祖先骨**且帧重叠，或发生外部（GUI）编辑；否则放行并在 warnings 说明。读工具保持严格 |
| 版本只因真实改动而变 | 工具执行期间屏蔽 depsgraph 回调；拖时间轴/播放不算编辑；写工具成功后显式 +1 |
| owner | op 记录 `owner`；别人 revert/reapply/set_influence → `E_OWNER`；`ab_toggle(agent_id)` 只拨自己的轨 |
| `plan_scopes`（派单时天然避开） | 协调者把计划的任务 scope 先过一遍：两两 hard/related 冲突、与现有租约冲突、建议并行批次（父骨任务先做、同骨重叠不同批）。任务可声明 `reads`（如复制的源窗）：别人要改的骨×帧落在它要读的范围里 = `read` 依赖，写者先做 |
| GUI 修复列表 | 每行标签后面带写它的 agent（如 `· cp`），源已变的复制带 `· 源已变,需reapply`；用户自己的修复标签不变 |
| 读依赖的运行时提醒 | motion_copy 写入时源窗正被别人认领 → warnings 提示"复制的是此刻的姿态"；之后任何人写到某个复制的源（同骨，world 空间连祖先骨）→ 该 op 在 list_ops 里带 `stale`（谁改的、哪段帧、怎么修），reapply 后自动清除 |

纯逻辑在 `agent_claims.py`（无 bpy，`tests/test_agent_claims.py` 覆盖）。e2e_concurrency 45/45：
抢同一 scope 只批一个；4 个线程 agent 经真 socket 各写 3 次、链式 expect_version、零误报；祖先骨被改 →
子骨 owner 收到 E_STALE；读工具不再推高版本；派单批次 `[[spine, head-later], [armL, armR], [handL-late]]`；
读依赖：改上臂的任务排在"复制左臂手势"之前，源窗被认领时复制会收到提醒；复制之后源被改 → 复制 op 标 `stale`，
reapply 后与新源一致（0.0003°）、标记清除；改无关的骨不误标。

## 3. 任务2：性能（结果零数值变化）

**尺子**：`tests/bench_baseline.py` 一遍里既计时（经 `_dispatch`，含桥开销）又录 golden——读结果、op 参数/
指标、写出的 delta 关键帧、受影响骨的求值矩阵，共 23 节；`bench_compare.py` 按**精确浮点相等**比对。
同一份代码跑两遍 golden 逐位一致（尺子本身可信）。

**测量先行**（cProfile）：`frame_set` 占 hold_pose/reapply/probe/烘焙的 80–88%。猜测"281 个网格变形
是大头"被实测否定（隐藏全部网格只快 8%，结果逐位一致但不值得改用户可见状态）——瓶颈是 RIG 自身
503 个 Rigify 约束。所以策略是**少求值**，不是求值更快：

| 优化 | 做法 | 为什么逐位一致 |
|---|---|---|
| socket 泵 | headless 主循环改为等 socket 线程的 Event（原：固定 70 ms 轮询）；GUI 定时器忙时 5 ms 复查；客户端 list+join 收包 | 只改调度时机 |
| 信号库 | 键从数据版本改为"外部改动纪元"——agent 写 delta 改变不了它的输入（npz 缓存+标注区间+设置），重建结果本来就逐位相同 | 输入相同 |
| 四元数乘法向量化 | `swing_twist_deg`/`delta_quat` 的逐帧 Python 循环 → `_qmul_rows` | 同一表达式、同一求值顺序、numpy ufunc 不做 FMA 合并 |
| probe_anatomy 单遍 | 原来对同一组采样帧扫 4 遍（方向/局部主轴/次轴/toward 误差）→ 1 遍；原版保留为 `_probe_slow` 兜底（owner 骨随帧变化时） | 同帧求值确定 |
| hold_pose 多骨 world_dir | 每骨各扫一遍 → 所有骨一遍；probe 轴每帧算一次共享 | 同上；单骨数学逐字搬入 |

## 4. 任务3：`motion_copy`（+ 验收工具 `compare_motion`）

- 源 = 当前**可见**姿态（含已有修复），先采样后写入（源窗与目标窗同骨重叠也精确）。
- `space="local"`（默认）复制关节局部旋转——随目标时刻的身体朝向走，时间平移和镜像手势都对；
  `space="world"` 按 GOAL 原规格"世界镜像（X=0，前方 −Y）后转目标骨局部"，人转了身就不跟身体走。
- 镜像不靠猜局部公式：`F = Rest_src⁻¹·S·Rest_dst`（S = X 反射），局部镜像 `Basis_dst = F⁻¹·Basis_src·F`
  ——由"世界镜像 + 父骨同样镜像"严格推导，rest→rest 精确；本 RIG 左右骨 F 与 diag(−1,1,1) 相差 <2e−5。
- `bone_map` 跨部位、`dst_range` 时间缩放（slerp 重采样）、`mode="add"` 叠加、`channels="rot+loc"`。
- 验收：`compare_motion {"op_id": …}` 直接按 op 验收（等价于写入返回的 `metrics.verify.args`，永远对应 op 当前窗口）——
  sonnet 反馈"手抄 19 骨×2 的骨名列表是最容易出错的一步"后加的。
- delta 相对可见姿态计算 → 叠在别的修复上也精确（旧工具相对基底动作，是"近似叠加"）。
- 实测：时间平移 0.00005°；镜像 local 19 骨（含 YXZ/XYZ Euler）0.0045°（胸骨系掌心镜像 0.005°）；
  world 镜像左右掌心 X 镜像 0.000°；时间缩放两端 0.00002°；add 0.00077°；窗外/revert 0.00000°。
  四元数骨有 ~0.005–0.03° 的 NLA float32 噪声底，验收阈值别设得比 0.03° 更低。

## 6. 自由加的工具：脚滑 + 下沉/悬空

`slide_report`（读）：按向导标注的 contact.L/R 区间逐段量 foot_ik 世界水平漂移（mm），flagged 行带现成的
`foot_lock` 参数。`foot_lock`（写）：把 foot_ik 钉在参考帧世界位置，`lock=xy`（默认，保留高度→脚跟抬起/

接触期处在 taper 之外。世界→局部经父骨（带 ARMATURE 约束）的求值矩阵换算；FK 腿直接报错。
fixture：右脚 44 段接触中 35 段漂 >10 mm（向导自己的 XY 锁之后、重定向到 RIG 仍然漂）；修后 35.1→0.000 mm，
高度/朝向不变（0.000 mm/0.0000°）。

`ground_report`（读，实时）——给旧工具 `fix_ground` 配的输入/输出工具。用与快照相同的三个脚底点（DEF-foot 头/尾、
DEF-toe 尾，取最低）读**当前可见姿态**；没人动过的脚与快照逐位相同（0.0 mm）。关键在**标定**：这些点是关节中心
不是鞋底，Teto 穿厚底靴，踩实时它们离地 7–8 cm（左 77.0 mm / 右 81.5 mm，43/44 段接触的中位数，p10–p90 仅 ±4–12 mm），
所以按"这只脚正常着地的高度"判断：比它低 = 下沉（`pen_frames`），接触期整段比它高 = 悬空（`floating`），并给出带好
`mode` 和 `rest_clearance` 的 `fix_ground_args`；快照与当前姿态差 > 1 mm 时警告"快照已过时"。fixture 上找出左脚 1 段、
右脚 7 段悬空接触和 6/7 处下沉；e2e：悬空接触 13.2..32.4 → −0.0..0.4 mm，下沉 16.5 → 0.0 mm，撤销逐帧还原。
（关节中心是近似：更准的做法是用网格的鞋底点，见 §10-14。）`mesh:true` 另外报出目标网格靴底（顶点组 足首D/足先EX）
的真实离地高度——只读诊断，见下面的发现。

**发现（需要你决定）**：用 `mesh:true` 量全片，接触期**靴底网格比地面低 1–2 cm**：每段接触最低点的中位数 左 −18.5 mm、
右 −11.6 mm，最深 −35 mm；左脚 882 帧、右脚 512 帧低于 −5 mm。向导设置里 target_floor_z = 0、vmd_floor_offset = 0，所以这是
真实的轻微穿地，而且是**全局**的。最可能的来源：向导 foot_lock 的闭环把脚钉在"绑定姿态最低点"这个**单点**鞋底模型上
（`sole_contact_offsets`），脚掌一翻转，真正的最低点就换成了别处。处理办法（都会改变动画，所以没替你做）：①导出准备里
设 `vmd_floor_offset` ≈ +15 mm 整体抬高；②把 foot_lock 的鞋底模型换成多点（脚跟+脚尖）或直接用网格最低点闭环。

## 10. 对整体设计的意见（按影响排序）

1. **delta 的参照系要统一到"可见姿态"。** 新工具都相对当前可见姿态算 delta，叠在别的修复上是精确的；
   旧的 hold_pose/clean_jitter/restore_accent 相对**基底动作**算（手册里叫"stacking 近似"）。两套语义
   并存，agent 很难推理"我这条修复叠上去到底是什么"。建议把旧工具迁到 `agent_pose`（采样可见姿态 →
   `pose_deltas`），golden 会变，所以单独一个版本做。代价是**顺序依赖**：下层修复被 reapply/revert 后，
   上层 delta 就不再精确——需要记录"同骨同帧段的上层 op"，并给一个 `reapply_chain` 一键按顺序重算。
2. **信号库冻结在第一次烘焙。** describe/get_series/get_joint_angles/validate/fix_ground 读的是 npz 快照，
   修完不变——agent 最容易在这里误判"没写上"然后叠第二层修复。现在靠提示词"快照类 vs 实时类"兜住；
   长期应二选一：写入后对受影响帧段增量重烘（信号库变成"当前"），或把两类工具改名/加 `source:"original"|"live"`
   参数，让语义写在调用里而不是靠记忆。fix_ground 用快照里的脚底高度，修过 foot_lock 之后会算错，属于同一问题。
3. **每个 op 一条轨，会越积越多。** 工作文件里已有 103 条空的 `NlaTrack.xxx` 轨（来源不明，疑为旧迁移/
   GUI 下推遗留）+ 15 条修复轨。轨越多每帧 NLA 求值越慢、面板越乱。建议：①清理空轨的维护工具；
   ②用户 commit 后提供"把已确认修复烘进一条 per-bone strip"的合并操作。
4. **IK/FK 要成为工具的一等公民。** 腿是 IK，FK 腿骨有 key 但写了看不见；膝朝向的 owner 却是 thigh_fk。
   现在靠报错/提示词告知。更好的是让工具自己映射：腿部请求自动落到 foot_ik（+膝 pole 目标）。
5. **骨架语义层值得单独一层。** 这次 overlap、motion_copy、并发的祖先判断都需要"语义父骨"（穿透 Rigify
   的 MCH/ORG/COPY_TRANSFORMS）。`agent_pose.semantic_parent` 现在是启发式 + 脊柱特例；建议在 rig_bake_spec
   旁边维护一张显式的"控制骨层级表"（每种 rig profile 一张），并由 e2e 校验。
6. **性能的地板是 RIG 求值（~1.9 ms/帧，503 个约束）。** 再往下快只能更少求值：同一批请求里缓存
   (版本, 帧) → 可见姿态采样；或给采样专用一个只含 RIG 的 view layer。网格不是瓶颈（实测隐藏全部网格仅快 8%）。
7. **参数校验要统一成"拒绝 + 提示最接近的合法名"——已做。** 以前新工具里有的拒绝、有的只在 warnings 里提一句，旧工具的包装
   用 `**_` 静默吞掉未知参数（拼错 `strength` 就按默认值执行；§7-11 的 dry_run 漏写也是这么来的）。现在全部工具都拒绝
   拼错的参数并提示（"stregth → strength？"）：新工具在各自的壳里校验，旧工具在分发层按签名统一校验
   （`agent_pose.reject_unknown_args`）。对合法调用零影响（golden 不变）。能力弱的模型常常不看 warnings，错误它躲不掉。
8. **数据目录存绝对路径本身就脆弱。** 这次修的是症状（外系统路径不信任）。更稳的是 .blend 里存相对 blend
   的路径，只在用户自定义目录时存绝对路径。

## 14. 2026-10-04 追加：骨盆旋转支点（重定向里程碑时静默修正）

- ARP 是**逐骨按世界朝向**映射的：源骨与目标骨的世界朝向偏移 Rs⁻¹·Rt 全片漂移 0.00°（骨盆、Spine1/2/3、颈、头、左臂四节，10 对全是）。

- Spine1 也不是"反向弯曲"：151–277 帧它相对骨盆的侧弯只有 5.3°（峰峰，与胯摆同相 +0.50）；真正的情况是 **Pelvis 和 Spine1 一起朝胯摆的反方向侧倾**
  （世界朝向 23.2° / 22.3°，与胯摆相关 −0.97 / −0.96），把胸往回带；再由 Spine2（13.7°）、Spine3（10.4°）把胸扶正（Spine3 世界朝向只剩 6.1°，与胯摆无关）。
- 丢的是**位置的杠杆**：源上这两个侧倾作用在骨盆关节**以上** 0.23 m 的腰段（Pelvis→Spine1 0.106 m、Spine1→Spine2 0.128 m），
  各把胸底往回带 0.045 / 0.049 m（与胯摆相关 −0.94 / −0.98）。Teto 上 Spine1 的朝向落在 `spine_fk`，它转的是 hips 头（z=1.031）**以下**的骨盆段
  （两髋中点→hips 头 0.095 m，带动的是胯，不是胸）——这一半假设成立；上半身链从 hips 头才开始，第一节 ORG-spine.001（0.109 m）拿的是 Spine2 的朝向，
  只往回带 0.025 m。差 ≈ 0.07 m，正好是胯相对肩 0.131 − 0.061。另外 Teto 躯干短：两髋中点→肩中点 0.372 m，源 0.523 m（比 0.711）。

**修法**（`core/target.fix_upper_body_follow`，纯后处理，只改 `spine_fk.001` 的四条四元数曲线）：逐帧采样 Teto 与源，
把 `spine_fk.001` 绕它的头（= hips 头）转一个最小旋转（上半身整体跟着走，胯、腿、脚、`torso_root` 不动），让 Teto 的肩中点落到"源的肩中相对髋中的偏移"上：
**左右偏移照抄源（1:1）**——髋和脚在水平面本来就是 1:1 跟源的，源上"胯摆肩不动"，Teto 上也得是肩不动；**前后偏移按躯干长度比 0.711 缩放**，
即前倾角度与源相同（按 1:1 会让短躯干的 Teto 鞠躬多弯约 1.4 倍）。垂直方向由肩到 hips 头的距离不变自然决定。旋转量 1.5 帧高斯平滑、每帧最多 20°，
源躯干倾斜超过 45–60° 时（地面动作、倒立）渐弱为零，髋线接近竖直的帧不修。写法 q′ = q·(Rw⁻¹·Q·Rw)（Q = 世界旋转，Rw = 该骨当帧世界朝向）。
动作上打 `mcd_upper_body_follow` 标记，幂等；需要该动作是活动动作、没有 NLA 叠加（否则跳过并说明原因）。源骨架取项目设置的 source_armature，

### 17.4 行为变化（工具手册需要同步的地方；手册归 dev/align，这里没改）

- `set_influence value=0` = 静音这条修复（strip.mute），再设回任何正数即恢复；面板显示 0.00。
- `effect_check`：结束时恢复每条轨原来的静音状态；不给 op/轨时**全部 agent 轨一起** A/B；默认采样帧用工具报的生效段。
- `reapply` / `compare_motion(op_id)` / `analyze_motion(baseline_op)`：同骨同帧、更新的上层修复在读的时候临时静音（结果里 `muted_newer_tracks`）。
- `hold_pose target=world_dir`：同一次调用里有父骨和它的子骨 → 报错，分两次调。
- 写工具：基底已在 `mcd_base` 上又指定了别的活动 Action → 报错（是基底本身则自动取消指定）。
- op 日志损坏 → 报 `OpLogCorrupt`，原文件改名 `agent_ops.json.corrupt-<时间>` 保留。
- MCP：`tools/list` 来自服务端；所有服务端工具都能调。
- 服务：HTTP 形式的连接直接断开；`MCD_AGENT_TOKEN`（Blender 与客户端都设）启用 token，默认关。
- GUI：「上一步/下一步」不再存 .blend；存盘只写当前打开的文件，打开的是检查点/恢复副本时拒绝存盘（提示用「恢复检查点」）。
