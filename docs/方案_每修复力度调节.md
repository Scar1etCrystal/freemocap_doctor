## 1. 现场调查结果（2026-10-01 实测，RIG 骨架）

- `mcd_base`：strip `base` → 向导烘的 action（foot_lock+ground_feet 叠名），REPLACE，正常。
- `AGENT_PREVIEW`：strip `agent_hold_505_570` → action `agent_hold_505_570_delta.003`，`applied_exp=1.084`（用户最后一次滑块位置）。滑块机制已验证工作。
- `mcd_agent`：**空**。log 里 `hold_pose_955539284` 仍是 committed——**场景与日志失同步的实例**（用户在 NLA 编辑器的 undo/删除可吞掉 socket 写的 strip；socket 走主线程，进 undo 栈）。
- 源骨架 `Armature` 上还有废案时代的 mcd_base/AGENT_PREVIEW 轨——agent 层已不指向它，**不动**。
- Blender 4.x 无 `nla_tracks.move()`；`nla_tracks.new()` 落栈顶=最后求值=最强。顺序只能靠创建顺序。
- NLA strip **不支持自定义属性**（连 `.get()` 都抛 TypeError）；action（ID）支持。`applied_exp` 已存 action 上，验证可持久化（存 .blend）。

## 2. 三个真相源与对账规则

| 真相源 | 存什么 | 谁写 |
|---|---|---|
| **场景 NLA**（RIG） | 轨/strip/mute/曲线（唯一决定画面） | 写工具、面板 |
| **action IDProp** | `applied_exp`（力度持久化，随 .blend 存） | `set_strip_exponent` |
| **op log**（JSON, data_dir） | 意图与状态：id/tool/params/frames/strip/**track(新)**/status/ts | 写工具、commit/revert |

**对账规则（sync）**：列表以 op log 为骨架（有哪些修复、叫什么、状态），以场景为事实核对：
- log 说 preview/committed 但场景找不到轨/strip → 该行标"丢失"（红），提供"清除记录"按钮（等价 revert 收尾）。
- 场景里有 agent 轨但 log 没有 → 标"未登记"，提供"登记"（极少见：手工建的轨）。
- mute 状态、applied_exp 一律以场景/action 实时读，**不存 log**（避免第二份真相）。

## 3. 轨道布局（D2）

- **轨名 = strip 名**（如 `agent_hold_505_570`）。冲突时 Blender 自动 `.001`，**创建后读回终名写进 log**（`op["track"]`，新字段）。
- strip 名生成规则不变：`agent_{tool}_{f0}_{f1}`；action 名 `..._delta`（`.00N` 后缀由 Blender 保证唯一）。
- **commit 不再搬轨**：状态变化只写 log（preview→committed），strip 留在原轨一生。轨的"身份"= log 记录，不是名字前缀。
- **revert = 删 strip + 删 action + 删（已空的）轨 + log 标 reverted**。
- 顺序：新轨创建在栈顶（new() 行为），= 最新修复最后求值 = 最新修正赢，与现状一致。
- 重叠区间天然无冲突（各在各的轨）——**修复现行 bug**（同轨重叠报 "no space"）。
- "是否 agent 轨"判定：`agent_track_prefixes()` 扩为 `("agent_", AGENT_PREVIEW, mcd_agent, mcd_agent 前缀)`；`mcd_base` 永远排除。
- 写工具的 `track_name` 参数（已加）默认改为 strip 名；`AGENT_PREVIEW`/`mcd_agent` 只留给迁移前的旧数据。

## 4. 数据模型（properties.py）

```text
MD_PG_AgentFixItem(PropertyGroup):
    op_id        String   # 主键
    label        String   # 显示名（strip 名）
    frame_start  Int
    frame_end    Int
    status       Enum     # preview/committed/reverted/lost
    exponent     Float 0–2, update=…  # 拖动 → set_strip_exponent(该 op 的 strip)
    muted        Bool, update=…       # 拖动 → 该 op 轨 .mute
Scene.mocap_doctor 扩展:
    agent_fixes        CollectionProperty(MD_PG_AgentFixItem)
    agent_fix_index    IntProperty          # UIList 选中
    agent_ops_rev      IntProperty          # op log 版本号（每次写/commit/revert +1）
```

- **同步时机**：面板 draw 时比对 `agent_ops_rev` ≠ collection 内记的上次 rev → 重建列表（按 op_id 匹配保留 exponent/muted/选中项）。**拖滑块不改 rev**（改的是场景曲线，不是 log）→ 拖动中绝不会被重建打断。
- rev 的 bump 点：socket 写工具落 op 后、commit/revert 后、面板按钮操作后。socket 与 UI 都在主线程，直接写 scene prop 安全。
- 持久化：collection 随 .blend 存，重启 Blender 后 draw 发现 rev 不匹配或列表空 → 自动重建，exponent 从 action `applied_exp` 读回，mute 从轨读回。**.blend 即完整状态**。

## 6. socket / MCP API

## 8. 连带发现：mmd_bake 被卡死（必须一起修）

现状：`mmd_bake`（RIG→MMD 烘焙）有两道检查会因 agent 层**永远失败**：
1. "MMR Rig 存在 NLA Track" → 我们有 mcd_base + agent 轨；
2. `_require_action(rig)` 要求 `anim.action` 非空 → 我们把它推到了 `mcd_base` 轨，`anim.action=None`。

而实际上 **agent 修正恰恰应该被烘进 MMD**（visual_keying 求值 NLA 栈，天然包含）。修法：
- 检查 1 放行 `agent_track_prefixes()` 内的轨，只拦陌生轨；
- 检查 2 的"覆盖范围"判定改为：`anim.action` 或 `mcd_base` strip 的 action，任一可用即可；
- 向导其余步骤不动（跑在源骨架上，D-向导分离原则）。

## 9. 迁移（现有两条 + 一次性）

`migrate_legacy_tracks(rig, data_dir)`，面板 draw / 服务启动时调用，幂等：
1. 扫 `AGENT_PREVIEW`/`mcd_agent*` 轨上的 strip；
2. 每个 strip：建同名新轨（栈顶）→ 把 strip 连 action 挪过去（新轨新建 strip+删旧 strip）→ log 对应 op 补写 `track` 终名；
3. 空的旧轨删除（`AGENT_PREVIEW`、`mcd_agent`）；
4. 已知实例：`hold_pose_955539284`（log=committed，场景 strip 已丢）→ 迁移后走对账标"丢失"，用户手动清记录；`hold_pose_955717888`（preview，action `.003`，exp=1.084）→ 正常迁移，力度/静音保留。
5. 源骨架 `Armature` 上的旧轨**不碰**（废案）。

## 12. 风险与边界

- **undo 吞 strip**（实测发生过）：对账标"丢失"是兜底；不做"防 undo"（Blender 机制，硬扛不了）。socket 写 op 后 `undo_push()` 保持（至少 undo 边界干净）。
- 拖滑块中 rev 变化（并发 socket 写）：概率极低（单用户），且重建保留 op_id 匹配项——最坏是拖动跳回当前值。
- UIList 行内操作符按钮与选择不同步（点眼睛≠选中该行）：可接受（眼睛是独立开关）。
- 修复数量大（>50）时 UIList 需过滤框：UIList 自带 filter 支持，暂不做（YAGNI，先跑）。
- `mmd_base` 的 action 也有四元数曲线——`set_strip_exponent` 只会被 per-op 寻址调用，永不触碰 base（log 里的 op 才有轨名）。
