# MoCap Doctor

面向 Blender 创作者的动捕动作清理向导。当前版本支持 Blender 4.3–4.5、固定的 arue Teto 2.01 和其 MikuMikuRig 控制器。动捕前端为 **GVHMR**，捕捉与重定向由 PoseCapture_Pack 完成，本插件负责重定向之后的后处理与 VMD 导出。源数据步骤与前端无关：旧 FreeMoCap 输出仍可作为工作文件使用，只需把「源数据来源」指到 `FreeMoCap`。

## GVHMR 前端

GVHMR 从单目视频重建重力对齐世界系下的 SMPL 动作，PoseCapture_Pack 负责运行它并把
动作重定向到 Teto 的 MMR 控制骨架。完整操作规程与映射文件见
[presets/bmap/README.md](presets/bmap/README.md)，要点：

1. PoseCapture 面板导入 pkl → 目标骨架选 `RIG-..._arm`（Teto 的 MMR 控制骨架）
2. 控制器类型 = **自定义映射**，映射文件 = `presets/bmap/gvhmr_mmd_fix_A_foot_ik.bmap`
3. 「预处理控制器」→ 把 `thigh_parent.L/R` 的 `IK_FK` 改成 **0**（全 IK）
4. 「重定向到 ARP」，人眼验收脚部与膝盖

修正版映射是必需的：PoseCapture 内置的 MMD 预设把 IK 标志挂在 `foot_spin_ik` 而非
真正的 `foot_ik.L/R` 上，在 arue 式 Teto 上会产生约 68° 的恒定脚部俯仰（实测）。
该映射对模型绑定敏感，换 MMD 模型必须重新验证脚部。

## 安装

1. 在 Blender 4.3–4.5 打开 `Edit > Preferences > Get Extensions`。
2. 从右上角菜单选择 `Install from Disk`，选择发布的 ZIP。
3. 启用 `MoCap Doctor`。面板位于 3D Viewport 右侧栏的 `MoCap Doctor` 页签。
4. 确认工作环境中的 `mmd_tools`、MikuMikuRig 和用于重定向的工具可正常使用。

## 项目约束

- 打开 PoseCapture 导出的源 `.blend`（旧流程为 FreeMoCap 工作文件）后再创建项目。插件会另存工作副本，不覆盖源文件。
- 项目固定为 `30 fps / fps_base 1.0`，只改播放帧率，不平移或缩放关键帧。
- 动捕范围使用绝对帧号，可以晚于第 1 帧开始；范围外的标定动作不处理。
- 项目数据保存在工作文件旁的 `.mocap_doctor/<工作文件名>/`，包括顺序编号的检查点和 JSON 报告。
- `.blend` Scene 是项目状态的权威来源；`project.json` 是便于检查的 UTF-8 镜像。每次恢复旧检查点前还会在 `recovery/` 自动保存当前状态。
- 目标对象必须来自 `arue_teto.blend`，名称和 MMR 约束结构必须保持不变；对象或骨骼若因重复导入自动添加 `.001`/`.002` 后缀，插件会把它视为同一固定对象，但同一侧出现多个候选时仍会停止并要求手工选择。  

## 使用顺序

按面板中的页面前进。每个自动修复先生成预览；播放检查后选择“接受并进入下一步”或“丢弃预览”。底部“上一步/下一步”只浏览页面，不改变数据；“恢复到某步骤执行前”才会打开检查点并把该步骤重置为可执行。手部修复页另有“返回修改坏区间”，会保留已有标注并撤销修复结果。

第 2 步「源数据校验」不改动任何数据。它先按骨骼命名判断源数据来源——GVHMR/SMPL 导入的骨架用 `f_avg_`/`m_avg_` 前缀，旧 FreeMoCap 用 `pelvis`/`hand.L`/`heel.02.L` 命名；判断不出来或判错时在面板上手动指定「源数据来源」。随后校验场景帧率是否为 30fps、源动作是否覆盖动捕范围、映射到的每根骨骼是否都有完整关键帧。源骨架按骨骼识别，**不要求固定的对象名**（GVHMR 导入的是 `Armature`，FreeMoCap 曾是 `import_synchronized_videos_rig`）。

第 3 步「源动作诊断」会同时给出两类手部提示：**动作跳变**（手腕速度异常，可能是坏数据也可能是快速动作，需要人判断）和**被遮挡**（填了 GVHMR 输出目录后，用 ViTPose 的手腕关键点置信度判断手有没有被挡住 —— 挡住的帧 HaMeR 是在猜，而猜的结果可能完全平滑，运动信号看不见）。两类都写进左右手的自动提示轨道，可编辑轨道的初始内容就是它们；面板上分开显示条数，改多了可以点「重新载入自动提示到可编辑轨道」恢复。判定阈值自动取每条视频自己的 5% 分位，不用手调。

手部坏区间、planted 区间和腾空区间都在 NLA 标注编辑器中处理。手部步骤只显示左右手两条轨道，planted 步骤只显示左右脚两条轨道，贴地步骤只显示腾空一条轨道。腾空区间按视频标注（人跳起离地到落地整段），自动提示（检测里"双脚同时离地"的帧）只作为初稿且不会覆盖已有标注——GVHMR 常把跳跃抹平，这条 take 上自动提示可能是空的，手标是常态。自动检测结果直接初始化可编辑轨道，不与人工结果另做隐式并集；Strip 名称中的 `[自动]`/`[手动]` 标明来源。默认按 `Ctrl+Shift+I` 标记入点、`Ctrl+Shift+O` 标记出点；**两端都包含播放头所在的那一帧**，同一帧按入再按出就是长度为 1 的区间（腾空只有一个帧的小跳就这么标）。只选中一个区间色块时，入点和出点命令只修改该区间；向外延伸会合并覆盖或连接的同方向区间。未选中色块时，入点始终开始创建新区间，出点只完成这个待创建区间。整个色块可以水平平移，也可以上下拖到另一条轨道来纠正左右手或左右脚标错；拖动边缘造成的缩放不会保存，端点应使用入点和出点命令修改。Blender 原生 `Delete/X`、面板删除按钮和“在当前帧拆分”都会写回权威区间数据。快捷键可在插件设置中修改并检查冲突。planted 标注期间，3D 视图会显示青色左脚、橙色右脚空心发光环，中心会露出脚部骨骼；当前脚不在 planted 区间时自动隐藏。标志允许渲染可见，但带有导出排除标记并会在退出标注时删除。

面板参数均提供鼠标悬停说明，完整说明见 `PARAMETERS.md`。

ARP/MMR 重定向仍为人工步骤。第 8 步的 Teto 模板字段只记录你使用的干净模板文件路径，不会自动导入模型；请先把 Teto/MMR 导入当前工作文件，再填写该路径。第 9 步的 Teto 根对象是模型最外层的 mmd_tools Root 空物体，不是 MMR Rig 或骨架。MMD Visual Bake 在固定结构、MMR 输入 Action 和完整帧范围全部通过验证时可以自动执行；检测失败时改为手工 Bake，再使用“检查手工 Bake 并清理 FK”。手工 Bake 若已由 MMR 工具移除约束，插件会改用 MMD Action 中实际存在的骨骼曲线验证。

第 11 步「贴地锁定」解决"走路飘"。旧的做法是"检测出接触帧再钉"，这条路走不通：GVHMR 的数据里**分不出什么时候是飘、什么时候是跳**——人站在地面而数据飞起 16 cm 时，检测照样标成 planted；反过来 GVHMR 会把真实的跳跃抹成"没离地"。改版把两件事分开：**人只标可观测的东西**——「腾空区间」（标**两只脚都不在地面**的那些帧：从最后一只脚离地之后起，到第一只脚触地之前止；一只脚在地面的过渡帧不用标，视频里一眼可见、次数少，在 NLA 标注编辑器里画）；**其余帧一律把最低的脚钉到地面**，无条件（PoseCapture 的做法，0001-0999 实测钉住帧残留中位数 0.16 mm）。判定只依赖"哪只脚更低"（数据里最可靠的信号），不再猜测接触。

钉的是**踝骨**，而鞋底在它下面 5.6 cm——这个落差是模型自己的绑定几何（PMX 建在 y=0 上，踝骨静止高度就是它离鞋底的距离），插件跑这一步时从模型上直接量，不是手调常数。所以"地面高度=0"是真的让**鞋底**落在地面上；步进顺序上它排在 Mesh 穿地修复之前，后者再把网格的残余穿透（脚掌俯仰带来的几毫米到一厘米）清零。

腾空段不是补一条线，而是**按物理弹道重建**：锚点取两端被钉住的已知高度，重力 9.81，飞行时间取标注区间的长度——高度由时长唯一决定（对称弹道 h = g·T²/8），GVHMR 压扁的跳跃因此飞回它应有的高度，漂移修正也随弹道一并穿过飞行段（不会起跳虚高、落地沉降）。对区间长度敏感（T² 关系）：多标两帧跳高约多 20%，所以**标得越准越好**，预览把关。超过 24 帧（0.8 秒，物理上是 78 cm 的跳）或贴到片头片尾缺锚的区间退化成两端平滑插值，报告里会注明。

非腾空段的修正曲线**先平滑再限速**（默认 10 mm/帧），换脚和台阶变缓坡；腾空段不受限速约束（真实起跳速度远大于它，限速会把起跳削平）。报告里另有一份**"疑似漏标"清单**：非腾空帧中脚离地很高的连续段——漏标的跳跃会被这一步压平，看到清单就回去补标。**这一步必须在 MMD Visual Bake 之前跑**，它靠 MMR 约束把修正传给模型，Bake 之后再跑会直接报错并提示恢复。

第 13 步「脚滑分析与 XY Lock」在位置锁之外还有**闭环稳定**，同页同预览、无开关：每个 planted 段取中位帧作锚，逐帧量 MMD 侧足首的**求值后世界位姿**（网格和 bake 真正跟随的骨头），与锚的差反向写进脚 IK——位置和旋转三轴全锁，含朝向。它锁的是"看到的脚"而不是控制器通道：位置锁实测把脚踝钉到 0.1 mm，足首却仍能在段内摆 9–19°（脚绕冻住的踝打转），闭环直接量到那根骨头，把残余压到收敛阈值内。锚的高度贴地化（planted = 接触）：锚 Z 换成该锚旋转下足底贴地的踝高，踮脚/翻滚姿态不被压平。同一步内先做**骨盆修约**（`骨盆修约上限`，默认 25 mm）：按源骨架腿长比逐帧重解骨盆高度写进 `torso_root`——模型腿按比例偏长会把膝拉直、骨盆把脚带离地面，身体下沉让腿恢复弯度、脚够回地面；双脚同植取更低解，摆动帧同式，修正曲线平滑后硬钳在上限内。段首尾各裁 2 帧、外圈 2 帧缓出。**真实的原地碾转会被一起冻死**：有碾转的段先把那几帧从 planted 删掉再跑。

两条路径都先判断腿究竟由谁驱动，再决定动不动那六根曲线：**MMD 原生腿 IK 正在工作时**（`ひざ.L/R` 上的 IK 约束指向 `足ＩＫ` 且 influence 不为 0）→ 删除 `足/ひざ/足首.L/R` 六根 FK 曲线、保留足 IK，这是传统 MMD 工作流；**腿由 FK 曲线驱动时**（本流程的 PoseCapture 重定向就是这种，原生腿 IK 的 influence 是 0）→ 保留这六根曲线并跳过清理断言，因为删掉它们会让腿直接回到静止姿势、脚下僵住。一键清理按钮在 FK 驱动的文件上会直接拒绝执行并说明原因。

导出准备按顺序做四件事。一，把 `teto_global_correction` 与 `全ての親` 已有动作按矩阵组合，并清掉校正 Empty 自己的曲线；**没执行过「Teto 全局扶正」时该 Empty 不存在，这一步整体跳过**（GVHMR 源本身已对齐重力，不需要那个手调倾斜，跳过是正常的）。二，按上面的驱动方式处理腿：IK 驱动 → 删除六根腿 FK 曲线；FK 驱动 → 保留曲线，并**把「关闭足ＩＫ / つま先ＩＫ」写进动作**，导出器会把它写进 VMD 的 IK 开关段，MMD 和 mmd_tools 的导入器都会回放，接收方不用再手动关。三，MMR 手部导出清理。四，往 `全ての親` 写入 VMD 地面 Z 偏移。

开始前会弹出 MMR 手部导出清理提醒：MMR 为编辑创建的 `手IK.L/R` 不是模型原生 MMD 骨骼。插件会确认 MMD Bake 已将可见上肢完整写入真实的 `腕/ひじ/手首.L/R`，再恢复肘部原本的层级、清除引用手 IK 的约束并删除这两个临时控制骨。`ひじ` 从 `腕` 换回 `腕捩` 之后会**按换父级前记录的世界矩阵重新写关键帧**——姿态骨骼的关键帧是相对父级解释的，而 `腕捩` 本身带着扭转姿态，只换层级会让整条小臂甩出去（实测 0.53 的矩阵误差）。此过程只改当前工作副本，预览前会创建检查点；不会改 PMX 或原始 Teto 模板。上肢烘焙不完整、骨架结构不符合固定 Teto，或清理前后姿势不一致时都会停止导出。其它带关键帧的重名骨骼仍会阻止导出并列出冲突。接受预览后，请隐藏 MMR Rig 检查动作。

最后在插件面板填写 `.vmd` 保存位置并直接导出；位置可以填文件（`F:\out\舞.vmd`）或文件夹（取工作文件名），插件会以 Teto 的 mmd_tools Root 为活动对象调用导出器，避免文件选择窗口丢失对象上下文。

## VMD 回导（验收）

回导到普通 Teto 模板可以直接导入；回导到 **MMR 模板**则必须先在那个模板里跑一次「准备接收模板」，否则导入的曲线会被 MMR 的约束压掉，表现为手臂僵在原地、只有躯干动时被拖着走。该按钮在插件面板顶部、尚未建立项目时显示。

它会删除 MMR 手臂控制绑定（控制骨架、`手IK.L/R` 辅助骨、驱动约束）、恢复 `ひじ` 父级为 `腕捩`、关掉手臂 IK、清掉旧动作，并把当前帧归到 1。模板只需准备一次并存盘。有一点必须记住：

- **它保留 mmd_tools 自己的 付与 绑定**（`mmd_additional_rotation`、`mmd_tools_at_dummy`）。腿的蒙皮挂在 `足D/ひざD/足首D` 上，删掉这些绑定会出现“骨骼照常动、腿的网格冻在静止姿势”。若某个模板曾被旧版本误删，用 MMD 面板 → Model Setup → `Assembly:` 一行的 **Bone** 按钮重建（它右边的垃圾桶是反向操作，别点）。

无论回导到哪种模板，**导入前当前帧都要停在 1**：mmd_tools 的 VMD 导入器把动作放在当前帧起，停在别的帧会让整段动作整体后移，前面留出一段定格的静止姿势。

当前版本不包含 LLM、WSL、Hermes、外部聊天软件连接或通用骨架映射。
